### The warning gate is stricter than it looks

The pool's CI greps its build log for `warning:` and fails the run on any hit
(`.github/workflows/lean_action_ci.yml`), and its `lakefile.toml` builds every library with
`weak.linter.mathlibStandardSet = true` — mathlib's whole syntax-linter set (`style.longLine`,
`style.show`, `style.openClassical`, `style.multiGoal`, `unusedDecidableInType`, …), none of which
a project's own lakefile would otherwise turn on. A library that builds silently at home can still
emit hundreds of warnings inside the pool.

So `lakefile.toml` on this branch mirrors the pool's `[leanOptions]` block verbatim, and the fixes
are in the code rather than in the options:

| Warning | Count | Fix |
| --- | --- | --- |
| `style.show` | 614 | `show` that *changes* the goal is `change` |
| `style.openClassical` | 38 | file-level `open scoped Classical` → `open scoped Classical in` per declaration, or `classical` in the proof |
| `style.longLine` | 16 | rewrapped |
| `unusedDecidableInType` / `unusedFintypeInType` | 12 | binder dropped (`omit … in` where it comes from a `variable`), `classical` in the proof |
| `style.docString`, `style.whitespace`, `style.multiGoal` | 4 | as advised by each linter |

### `lake exe lint-style <library>` under-reports

Passing the library name lints only part of the tree: locally `lake exe lint-style Jacobian` was
silent while the pool's `lake exe lint-style LeanPool` found six style errors in these same files
(three trailing-whitespace, three characters outside mathlib's unicode allowlist — `∂̄`'s combining
macron and `⟺`). Pass every module by name instead:

```bash
lake exe lint-style $(git ls-files 'Jacobian/*.lean' Jacobian.lean \
  | sed 's/\.lean$//; s#/#.#g' | tr '\n' ' ')
```

## Assembling the PR

```bash
python3 scripts/make_pool_pr.py          # writes build/pool-pr/
python3 scripts/make_pool_pr.py --check  # staleness check

# proof-size gate, run through the pool's own measuring code rather than an approximation of it
curl -sLo .pool-quality.py \
  https://raw.githubusercontent.com/Vilin97/lean-pool/main/python/lean_pool/quality.py
python3 scripts/poolsize.py
```

That emits `LeanPool/JacobianDiffgeo.lean` + `LeanPool/JacobianDiffgeo/**` with the module prefix
rewritten (`Jacobian.* → LeanPool.JacobianDiffgeo.*` — only `import` lines change, since the
library never names its own modules elsewhere), plus the `projects.yml` card as a fragment to
splice in. After copying into a pool checkout, run `lake exe mk_all` — the pool's `LeanPool.lean`
index lists every module in the repository, so it grows by our 213 lines.

The entry module is not this repo's `Jacobian.lean` verbatim. The pool generates it
(`quality.py::_write_project_card`) as header → imports → **project card**, and rejects a PR whose
card disagrees with `projects.yml`, so the script renders that card itself, from the same values
as the YAML fragment, and asserts the two agree. One consequence worth knowing: the card is a Lean
file, so a `Main declarations:` line naming all three headline theorems would be 157 columns and
the pool's own build would warn on it — the card names the headline theorem, and the other two
live in `main_results`, which is prose and wraps.

The generated tree has **not** been compiled inside a pool checkout; the rewrite is the same one
the lean-eval overlay uses, which does build, but that is an inference, not a test — which is what
the dry-run workflow below is for.

## What is left

Nothing in the library itself; what remains is the pool's review of PR #334 — five LLM review
dimensions (faithfulness, novelty, significance, sources, code quality) on top of their CI.

`.github/workflows/pool-dryrun.yml` (on `pool-bump-4.33`) assembles the payload into a real
lean-pool checkout and runs *their* gates — pins must match, `lake build LeanPool.JacobianDiffgeo`,
a warning scan over that build log, `lake exe mk_all --check` against the index the PR ships
(`scripts/pool_index.py` regenerates it without a toolchain), `runLinter`, `lint-style`, and
`python -m lean_pool.quality` — so the PR is only opened once that is green. Nothing in it ever
writes to the pool repository.

## Notes for the port (v4.32.2 → v4.33.0-rc2)

4.33 tightened `rw`'s keyed matching: the target must now be type-correct at `implicit`
transparency, so a subterm that only type-checks by unfolding a semireducible definition blocks
*every* rewrite in that goal — usually reported as "did not find an occurrence of the pattern"
even though the pattern is plainly there. Three shapes of it occur here, with the fixes used:

1. An `Opens`-`≤` proof standing where `MeroGermOn.restrict` expects `↑V ⊆ ↑U`. Name the subset
   proof in a `have` at the `Set`-level type and use that, or discharge the step with
   `exact`/`refine`, whose matching is full defeq.
2. Cover-shaped definitions (`coverOfP`, `coverStar`/`coverV`/`coverW`/`coverU`, `pairCover`)
   whose fields have to unfold before `C0`/`C1` line up. These are now `@[reducible]`.
3. A proof applied through the semireducible `MeromorphicOnX`. Name it in a `have` with its
   stated type.

Related: a rewrite chain through `mk_neg`/`mk_add` cannot instantiate the proof-valued arguments
of `MeroGermOn.mk`, so `GermSpace` now states `mk_sub` directly.

rc1 → rc2 was smaller and entirely mechanical: the new `style.haveILetI` linter (`haveI`/`letI`
are `have`/`let` when the goal is a proposition) and a batch of mathlib renames — `Set.mem_setOf_eq`
→ `Set.mem_ofPred_eq`, `Set.restrict` → `Set.domRestrict`, `ContinuousOn.restrict` →
`ContinuousOn.domRestrict`, `ENat.toNat_coe`/`coe_toNat`/`map_coe` → their `natCast` spellings.
The pool moves its pin often; re-run everything here against `lean-toolchain` and the mathlib rev
in *their* `lake-manifest.json` before opening a PR.
